# 업무 자동화 실측 기록

가상 학생 60명의 성적 안내 메시지를 검토·확정·모의 발송하는 데 걸린 사용자 업무 시간을 한 번 측정한 기록이다.
- 서버 처리량이나 API 응답 시간을 잰 것이 아니다. 화면을 조작한 사람이 걸린 시간이다.
- 이 서비스는 실제 학원 업무에 쓰인 적이 없다. 측정은 가상 데이터로 개발자가 직접 했다.

## 1. 측정 목적

엑셀로 들어온 반별 출결·과제·성적으로 학부모 안내 메시지를 만든 뒤, 검토부터 발송 확인까지를 웹서비스로 끝내는 데 얼마나 걸리는지 확인한다.

## 2. 측정 환경

| 항목 | 내용 |
|---|---|
| 측정일 | 2026-11-23 |
| 대상 | 배포 서비스 https://academy-message-manager.vercel.app (Vercel · Render · Neon) |
| 대상 버전 | 측정 당일의 배포본. 정확한 커밋은 기록하지 않았다 |
| 발송 | 모의 발송(`MockSender`). 실제 문자·이메일은 보내지 않는다 |
| 측정자·횟수 | 개발자 본인, 1회 |
| 측정 도구 | 사람의 시간 측정. 별도 로그나 화면 녹화는 남기지 않았다 |

## 3. 가상 데이터 구성

- 학생 60명, 반 5개, 반마다 12명. 모두 가상 데이터다.
  - 정규반: `고1 토6A`, `고1 토6B` / 내신 대비반: `검증고2 토6`, `테스트고2 토6`, `가짜고2 토6`
  - 학생 `가상학생01`~`60`, 보호자 `벤치보호자NN`, 보호자 이메일은 모두 예약 도메인 `example.invalid`
- 학생 등록: [`backend/scripts/seed_benchmark.py`](../backend/scripts/seed_benchmark.py). 업로드할 때 모든 행이 기존 학생과 연결되도록 학생·수강(시작일 2026-09-01)·보호자 이메일을 미리 넣는다.
- 업로드 파일: [`data/가상학생-60명-5개반-토6.xlsx`](../data/가상학생-60명-5개반-토6.xlsx). 시트 1개, 반 블록 5개, 학생 행 60개.
- `example.invalid`는 Mock Sender가 항상 성공으로 처리한다. 그래서 이 측정에는 **발송 실패와 재시도가 없다**.

## 4. 측정 시작·종료 조건

| 구분 | 조건 |
|---|---|
| 시작 | 엑셀 업로드 직후 |
| 종료 | 모의 발송 완료 후, 메시지 처리 현황 화면에서 결과 확인을 마친 시점 |
| 포함 | 메시지 검토, 내용 확정, 모의 발송, 처리 현황 확인 |
| 제외 | 로그인, 서버 유휴 정지 후 기동(콜드 스타트), 엑셀 업로드, 학생·반 사전 등록 |

## 5. 측정 시나리오

1. 관리자가 반 5개를 등록하고 `seed_benchmark.py`로 학생 60명을 등록한다(측정 전 준비).
2. 로그인 후 성적 안내 화면에서 업로드 파일을 올린다(측정 전).
3. **(시작)** 업로드로 만들어진 메시지 초안을 검토하고 내용을 확정한다.
4. 확정한 메시지를 모의 발송한다.
5. 메시지 처리 현황에서 발송 결과를 확인한다. **(종료)**

검토 단계에서 반 단위 일괄 처리를 썼는지, 학생별로 검토했는지는 기록하지 않았다.

## 6. 측정 결과

| 항목 | 결과 |
|---|---|
| 처리 대상 | 학생 60명의 성적 안내 메시지 |
| 걸린 시간 | **약 5분**(1회) |
| 발송 결과 | 모의 발송. 실제 전달 없음 |

**비교 기준에 대해**
- 같은 업무를 손으로 할 때 약 30분이 걸린다는 값이 있다. 이 값은 개발자가 학원 조교로 근무할 때(측정 시점 약 2년 전) 엑셀에 학생 데이터를 넣고 학부모 성적 안내 메시지를 직접 보내던 경험을 기억해 추정한 것이다.
- 두 값은 같은 조건에서 비교한 실험이 아니다. 학생 수, 메시지 내용, 발송 수단(실제 문자와 모의 발송)이 다르고, 수작업 시간은 측정값이 아니다. 그래서 단축률(%)로 환산하지 않는다.

## 7. 측정의 한계

- 1회 측정이라 편차를 알 수 없다.
- 측정자가 개발자 본인이라 화면 사용에 익숙하다. 처음 쓰는 직원의 시간과 다를 수 있다.
- 실제 문자·이메일 발송, 발송 실패 처리, 재시도 시간이 들어 있지 않다.
- 엑셀 업로드(파일 선택·미리보기 확인·확정), 로그인, 콜드 스타트 시간이 빠져 있다.
- 정확한 측정 버전(커밋)과 시간 기록 원본이 남아 있지 않다.
- 이 문서를 쓰면서 측정을 다시 수행하지는 않았다.

## 8. 재현 방법

`seed_benchmark.py`는 `ACADEMY_DB_MODE`가 `production` 또는 `test`일 때만 실행된다(로컬 개발 DB는 대상이 아님). 측정 당시처럼 배포 환경에서 재현하는 절차는 다음과 같다.

1. [Neon 배포 가이드](deployment/phase11_5_a_neon_guide.md) 3절대로 대상 DB에 연결하는 셸을 준비한다.
2. 관리자 계정으로 반 관리에서 위 반 5개를 만든다.
3. 같은 가이드 [7-1절](deployment/phase11_5_a_neon_guide.md#7-1-업로드-벤치마크-학생-60명-선택)대로 `python scripts/seed_benchmark.py`를 실행하고, `--check`로 확인한다.
4. 로그인해 `data/가상학생-60명-5개반-토6.xlsx`를 업로드한다. 수업일은 2026-09-01 이후로 고른다.
5. 4절의 시작 조건에서 시간을 재기 시작해, 5절의 순서대로 진행하고 종료 조건에서 멈춘다.
