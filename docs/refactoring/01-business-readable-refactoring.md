# Business Rule Refactoring: 비즈니스 요구사항 가시화

이 문서는 전체 **Refactoring 1** 범위 중 비즈니스 규칙을 읽기 쉽게 만든 작업을 설명합니다.

## 목표

기존 화면 동작과 DB 스키마를 유지하면서, 문자열 비교에 숨어 있던 학원 운영 규칙을 코드의 이름과 타입으로 드러낸다.

## 적용 내용

- `ClassType`: 정규 수업과 내신 대비 수업
- `EnrollmentStatus`: 재원·휴원·퇴원 및 보강 신청 자격
- `AttendanceStatus`: 출석·결석 및 보강 안내 필요 여부
- `AchievementGrade`: A/B/C 성취도
- `MakeupStatus`: 신청·승인·완료·취소와 허용 상태 전이
- `SendStatus`: 대기·성공·실패·제외
- `MakeupGuidancePolicy`: 출결과 보강 상태에 따른 보호자 안내 문구
- `LearningMessageComposer`: 선택된 학습 항목만 포함하는 메시지 생성 규칙

## 보존한 호환성

Swing 화면과 Oracle 테이블이 사용하는 문자열 코드는 그대로 유지했다. 기존 `Util` 클래스는 화면 표시용 어댑터로 남기고 내부 변환을 도메인 타입에 위임한다.

## 확인된 비즈니스 규칙

1. 보강 신청은 재원 학생만 가능하다.
2. 출석 학생에게는 보강 안내를 포함하지 않는다.
3. 보강 신청·승인 상태는 예정 안내, 완료 상태는 완료 안내를 사용한다.
4. 완료·취소된 보강은 다른 상태로 되돌릴 수 없다.
5. 학습 메시지는 실제 데이터가 있고 사용자가 포함을 선택한 항목만 출력한다.
