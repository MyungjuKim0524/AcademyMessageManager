# 백엔드 비즈니스 요구사항

## 성적 데이터 등록

- 운영자는 CSV 또는 XLSX에서 수업·학생·출결·성취도 정보를 불러온다.
- 필수 열과 값이 유효하지 않으면 DB 반영을 막고 원본 행 번호를 표시한다.
- 동일 분반, 학생, 수업 회차, 성적은 중복 생성하지 않는다.
- 기존 성적이 같으면 건너뛰고, 달라졌을 때만 수정한다.
- 한 묶음의 반영이 실패하면 전체 DB 트랜잭션을 롤백한다.

## 보호자 안내 메시지

- 정규/내신 대비별 활성 템플릿을 사용한다.
- 예습·주간 과제·테스트 결과는 데이터가 있는 항목만 포함한다.
- 결석 학생에게 보강 상태에 맞는 안내를 포함한다.
- 템플릿 DB 조회 실패 시 기본 템플릿으로 메시지 생성을 계속할 수 있다.

## 발송

- 퇴원 학생과 이메일이 없거나 잘못된 학생은 발송에서 제외한다.
- 발송 성공, 실패, 제외 결과와 실패 사유를 기록한다.
- 실패 건은 운영자가 명시적으로 선택해 재시도한다.
- SMTP 및 DB 비밀값은 소스에 저장하지 않는다.

## 보강과 수강 상태

- 재원 학생만 보강을 신청할 수 있다.
- 보강 상태는 `REQUESTED → APPROVED/COMPLETED/CANCELED`, `APPROVED → COMPLETED/CANCELED`만 허용한다.
- 완료와 취소는 종료 상태다.
- 퇴원 처리 시 미완료 보강 신청을 취소한다.
