## 1. 성적 분석 (출결·성적 분석 → 성적 분석 탭)
### 왜 바꿨나
기존 화면은 회차별 입력 완료율·평균(운영 점검 지표)과, 모든 시험을 원점수 %로 한 줄에 섞은 추이 그래프("실력 변화로 단정하지 마세요" 경고)가 전부였다. 과제·출결은 쓰지 않았고 "누구를 왜 챙길지"에 답하지 못했다.

### 화면 (위에서 아래로)
1. **관심 필요 학생 (최근 4주)**: 규칙에 걸린 학생과 **이유 문장**(예: "어휘: 반 평균보다 15%p 이상 낮은 회차 4회", "주간 과제 C 등급 4회", "결석·미응시 4회 (결석 2, 미응시 2)"). '리포트 보기'로 바로 학생 리포트. '판단 기준' 접기 영역에 규칙 원문을 둔다.
2. **학생 학습 리포트**: 관심 이유(있으면) · 출결 요약 · **평가 항목별 카드**(항목 = 시험 열 이름) — 학생 %(실선)와 **같은 회차 반 평균 %(점선)** 그래프, 회차별 점수·반 평균·**반 대비(%p)**, 기간 평균 반 대비 · **수업별 출결·과제(예습/주간, C는 빨강)**.
3. **회차별 반 요약**(기존 평가별 요약 + 평가 상세): 맨 아래로 내렸다. 입력 현황은 보조 정보로 남겼다.

### 관심 필요 학생 규칙 (`analytics/service.py` `WATCH_*`) — 같은 날 개정(사용자 승인)
처음에는 "최근 4주 + 각 기준 4회 이상"으로 만들었다. 주 1회 반은 4주에 회차가 4개뿐이라 거의 걸리지 않았다(연속 하락 규칙은 회차 5개가 필요해 아예 걸리지 않았다). 그래서 **날짜 대신 학생별 최근 회차** 기준으로 바꿨다. 수업 빈도와 관계없이 같은 의미가 된다.

| 규칙 | 정의 |
|---|---|
| 판단 범위 | 평가 항목별 **점수가 있는 최근 4회차**, 학생의 **최근 4회 수업**. 최근 3개월(92일) 기록 안에서 |
| 점수 | 최근 4회 중 **3회 이상** 같은 회차 반 평균보다 15%p 이상 낮음. 점수가 **3회 이상** 있어야 판단 |
| 점수 흐름 | 최근 3회 동안 반 대비 위치가 **계속 낮아졌고 합쳐서 10%p 이상** 하락 |
| 과제 | 최근 4회 수업 중 예습 또는 주간 과제 C 등급 **2회 이상**(각각) |
| 출결 | 최근 4회 수업 중 **결석, 또는 출석했지만 그 수업 시험 미응시**가 2회 이상(수업당 1회만 셈). 인정결석은 세지 않음 |
| 대상 | 수강 대상(수강 기간·휴원 규칙 `eligible_on`)인 기록만, 퇴원 학생 제외 |
- **반 평균 대비 위치(%p) = 학생 만점 대비 % − 같은 회차 반 평균 %**(점수 입력된 학생 기준). 회차마다 난이도가 달라 원점수 %는 비교할 수 없으므로, 같은 회차 반과의 차이로 성장 흐름을 본다.
- 이유 문장 예: "어휘: 최근 4회 중 3회 반 평균보다 15%p 이상 낮음", "어휘: 최근 3회 반 대비 위치가 계속 낮아짐 (-2.0 → -7.0 → -13.0%p, 11.0%p 하락)", "최근 4회 수업 중 주간 과제 C 등급 2회", "최근 4회 수업 중 결석·미응시 2회 (결석 1, 미응시 1)".
- 개정 후 테스트: 경계값을 확인한다(예습 C 4회 중 1회는 미표시, 점수 2회뿐인 학생은 아무리 낮아도 판단 안 함, 인정결석·결석일 시험은 세지 않음). 백엔드 전체 121 PASS, 분석 화면 Vitest 8 PASS, build PASS.

## 2. 직원 삭제 (B안)
- 직원 목록 '삭제' → **경고창 1회**: "즉시 로그아웃, 다시 로그인 불가, 목록·담당 반 배정에서 사라짐, 되돌릴 수 없음. 업무 기록에는 이름이 그대로 남음."
- 서버(`DELETE /api/staff/{id}`):
  - **기록 없는 계정**은 진짜 삭제한다(세션·배정도 함께).
  - **기록 있는 계정**(로그인 1회도 포함)은 상태를 `DELETED`로 바꾼다. 로그인할 수 없고, 직원 목록·반 담당 목록에서 숨겨지며, 다시 활성화할 수 없다. 메시지 확정자·발송자 등 이력에는 **"이름 (삭제된 직원)"** 으로 표시된다.
  - 자기 계정과 마지막 활성 관리자는 삭제할 수 없다. 삭제된 계정의 이메일로 새 계정을 만들면 안내와 함께 거절한다.
  - 감사 기록 `STAFF_DELETED`(mode HARD/SOFT)를 남긴다.
- DB: **마이그레이션 011**(`chk_staff_user_status`에 `DELETED` 추가). 되돌릴 때 삭제 처리된 계정이 있으면 거부한다. **개발 DB에 적용 필요: `.\scripts\migrate-dev-db.ps1`**
