# 학생·반 관리 재구성 + 평가 관리 판단 (2026-11-20)

## 1. 학생·반 관리 화면 (관리자)
사용자 요청: 반 관리와 학생 관리를 나누고, 학생 등록 때 수강 등록을 같이 하며, 학생 관리 안에 전체 학생 / 반별 학생을 둔다.

| 탭 | 내용 |
|---|---|
| **반 관리** | 반 등록(엑셀 반 이름과 글자 그대로 같아야 한다는 안내 포함) · 반 목록(운영 중 / 운영 종료, '운영 종료된 반도 보기') · 이름 수정 · 운영 종료 / 다시 운영 · 삭제 |
| **학생 관리** (기본 탭) | 학생 등록(이름·학교·보호자 이메일 + **수강 반·수강 등록일**을 함께) → 아래에 '전체 학생 / 반별 학생' 전환. 반별 학생에는 휴원·복귀, 연락처 수정, **기존 학생 수강 추가**(다른 반도 다니는 학생) |

관리자가 아닌 직원은 기존과 같이 담당 반 학생 목록만 본다.

### '삭제'를 어떻게 정의했나 (설계 판단)
반에는 수업·출결·성적·안내 메시지가 연결된다. 그래서 DB가 이미 기록 있는 반의 물리 삭제를 막고 있었다(`RESTRICT` FK). 이 보호를 그대로 쓰고, 삭제를 두 가지로 나눴다.
- **삭제**: 기록이 하나도 없는 반만 지운다(예: `002 토2`처럼 잘못 등록한 반). 기록이 있으면 409 `CLASSROOM_HAS_RECORDS`와 함께 "운영 종료를 사용하세요"라고 안내한다.
- **운영 종료**: 모든 기록을 남긴 채 수업·업로드·안내·분석 화면과 담당 반 권한에서 숨긴다(기존 `classroom.is_active` 사용, DB 스키마 변경 없음). **다시 운영**으로 되돌릴 수 있다. 같은 이름으로 새로 등록하려 하면 "운영 종료된 반이 있으니 다시 운영하세요"라고 안내한다.
- **이름 수정**: 오타 정정용이다. 엑셀 반 이름과 같아야 업로드되므로 화면에 그 점을 안내한다. 유형(정규/시험 대비)은 템플릿·학교 규칙과 연결되어 있어 바꿀 수 없다(빈 반이면 삭제 후 재등록).
- 감사: `CLASSROOM_UPDATED`(바뀐 항목의 이전→이후), `CLASSROOM_DELETED`. 반 관리 변경은 이번부터 기록을 남긴다(리뷰 M1의 일부. 다른 관리자 변경 감사는 Phase 11 보안 점검에서 다룬다).
- 전체 학생 목록에서 운영 종료된 반의 수강 이력은 '운영 종료' 태그로 표시하고, 열 수 없게 했다.

### 학생 + 수강을 한 번에
`POST /api/students`에 선택 필드 `classroom_id`·`enrolled_at`을 추가했다(둘은 함께 보내야 함). 학생과 수강을 **한 트랜잭션**으로 저장하므로 "학생만 생기고 수강 등록은 실패"하는 일이 없다. 반을 고르지 않으면 기존과 같이 학생만 등록한다. 연속 등록을 위해 저장 뒤 이름·학교·이메일만 비우고 반·날짜는 남긴다.

## 2. 평가 관리 — 판단: **데이터 구조는 유지, 화면을 '평가 항목' 중심으로 재구성**
사용자 의견: 평가 관리는 학생 성적을 DB에 관리할 "행 이름"(예: 문법·문학·독서, 어휘)을 정하는 곳이어야 하지 않나? 지금은 회차별 응시 현황이 나와 목적과 맞지 않는 것 같다.

**객관적 판단**
- 점수는 반드시 **회차(날짜가 있는 시험 한 번)** 에 저장되어야 한다. 같은 '어휘'라도 회차마다 다음이 다르기 때문이다.
  - 만점이 다르다(예시 엑셀: 15·20·25).
  - 응시 대상(그날 수강·휴원)과 미응시가 다르다.
  - 재업로드가 고칠 대상도 그 회차다.
  - 따라서 "항목 이름만 있는 표"로는 점수를 담을 수 없다. 지금의 회차 단위 구조(`assessment` = 회차, `assessment_result` = 학생 점수)가 맞다. **"DB 행 이름을 위해 존재한다"는 전제는 절반만 맞다.** 항목 이름은 회차의 이름(`title`)으로 이미 저장되고 있다.
- 다만 사용자의 지적에는 실제 문제가 있었다. 화면이 회차를 시간 순으로 나열만 해서 **"이 반의 평가 항목이 무엇인지"가 보이지 않았다.** 업로드가 매주 회차를 만들기 때문에 목록이 계속 길어진다.
- 평가 항목 마스터 테이블(항목을 먼저 등록하고 엑셀 열을 대조)은 **도입하지 않는다.** 항목은 엑셀 반 블록의 시험 열 머리글이 이미 정의하고 있다. 마스터를 두면 19개 반마다 항목을 미리 등록해야 하고, 머리글이 조금만 달라도 업로드가 막힌다. 얻는 것보다 관리 비용이 크다. 항목 단위 성적 추이 분석이 필요해질 때 다시 검토한다.

**변경**
- 평가 관리 탭 머리글: `평가 항목 N개 · 회차 M개`.
- 항목별 묶음 행: 회차 수, 만점(회차마다 다르면 '회차마다 다름'), 최근 평가일. 펼치면 회차별 평가일·연결 수업·만점·입력 현황·평가 수정이 나온다(최근 회차부터).
- 설명 문구: "평가 항목은 엑셀 시험 열 이름입니다. 업로드할 때마다 수업일별 회차가 만들어지고 점수는 그 회차에 저장됩니다."
- 평가 등록(수동 회차 추가) 창에 기존 항목 이름 태그를 둔다. 누르면 이름과 최근 만점이 채워져 같은 항목으로 묶인다(이름 오타로 항목이 갈라지는 것 방지).
- 백엔드·DB 변경 없음(화면에서 이름으로 묶음).

## 3. API (추가만)
| 경로 | 내용 |
|---|---|
| `GET /api/classrooms?include_inactive=true` | 관리자: 운영 종료된 반 포함(운영 중 먼저). 다른 역할은 무시되고 기존과 같음 |
| `PATCH /api/classrooms/{id}` | 관리자+CSRF: `{name?, is_active?}` |
| `DELETE /api/classrooms/{id}` | 관리자+CSRF: 기록 없는 반만 204, 아니면 409 `CLASSROOM_HAS_RECORDS` |
| `POST /api/students` | 선택 `classroom_id` + `enrolled_at`(함께), 한 트랜잭션 |
| `GET /api/students` | 수강 요약에 `classroom_active` 추가 |
